## 一句话

源镜是一个**AI 分析师团队工作台**：你向 AI 分析师们下达任务，
它们调用数据（采集、清洗、分析、可视化）并把结论交付给你。
数据采集是这支团队的"后勤"，不是用户日常操作的对象。

## 核心认知（2026-10-15 方向修正）

- 程序围绕 **AI** 组织，不围绕数据组织；数据是给 AI 的燃料
- 每个板块由专门的**子 agent** 负责：有名字、有职责、有产出物
- 采集完成后其入口可以收起；用户只在对话里看到"管家汇报：已取回 / 已整理"
- 界面语言一律是"和谁说话、要什么产出"，不暴露技术状态

## 子 agent 阵容（2026-10-15 提案，命名待确认）

| Agent | 职责 | 现有能力承接 |
|---|---|---|
| 源镜（总管） | 接单、派活、汇总、答疑 | 工作台对话 + 路由 |
| 数据管家 | 登录、取数、清洗入库、汇报 | collect / store 质量筛选 |
| 受众分析师 | 互动者画像与群体洞察 | analyze/creator |
| 内容分析师 | 作品表现诊断与对比 | analyze/ai 作品评价 |
| 传播策略师 | 选题、方案、内容优化 | analyze/enterprise |
| 复盘顾问 | 报告整理、执行反馈回顾 | report / 指标补录 |

## 给谁用

- 目标用户：企业自媒体运营者（当前场景：组长负责的企业账号运营）
- 使用形态：一台 Windows 电脑、一个程序、双击即用
- 明确不是：多用户平台 / SaaS / 任何需要服务器常驻的东西

## 用户的主线流程（AI 视角）

1. 首次打开 → 配 Key、登录（由数据管家代劳）→ 认识 AI 团队
2. 对团队说话：例如"看看最近谁在点赞我的视频"
3. 总管派单：数据管家取数清洗 → 分析师出结论 → 策略师给方案
4. 产出物沉淀在会话旁：方案、报告、可打开、可导出
5. 复盘：向复盘顾问要历史对比

## 不做什么（边界）

- 不做服务器、不做多用户、不做 Web 端（服务器方向已退役）
- 不实现抖音请求签名、不绕过任何技术保护措施
- 不做自动发布 / 自动私信等"代操作"
- 不做没有真实分工的"角色扮演"：每个 agent 必须有独立提示、任务类型与产出物
- 稳定与配额安全优先于速度

## 硬性指标（验收口径）

- 全新电脑：下载 → 双击 → 10 分钟内与 AI 团队完成一次完整任务（当前差距见 [status.md](status.md)）
- 程序内不出现"竹梦村"等历史项目名（产品名待定，见下）
