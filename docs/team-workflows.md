# 团队连续协作

普通问答仍由一名成员回答。受众分析、作品诊断和传播方案进入程序管理的固定流程。

## 使用

- “仅用已有数据，分析受众和作品，给我三个下周选题”：整理数据 → 受众分析 → 作品诊断 → 制定方案 → 汇总交付。
- “仅用已有数据，分析互动人群”：整理数据 → 受众分析 → 汇总交付。
- “仅用已有数据，诊断作品表现”：整理数据 → 作品诊断 → 汇总交付。
- “更新数据后生成方案”：由数据管家先检查登录态，登录和采集分别通过现有确认卡授权，再进入分析。
- “生成方案”按钮：使用已有数据和当前会话进入同一个协作入口。

拒绝登录或补采后，程序只根据已有数据继续；缺失的分析阶段会明确标为资料不足，任务标为部分完成。

## 成果与恢复

任务卡显示各成员的状态。“查看阶段成果”可查看分析、方案、样本范围、数据冻结时间和引用依据。
完整方案沿用原有右栏、人工复核记录和导出报告功能。

- **继续未完成步骤**：沿用原来的数据快照和已完成成果，从失败、停止或上次未结束的步骤继续。
- **按最新数据重做**：新建任务、重新读取本机数据；原任务及成果保留。是否联网采集仍遵循原请求的范围及确认流程。
- 程序重启后，从历史会话重新打开任务即可继续；不会在启动时自动执行浏览器操作。
- 已成功采集的结果会先记录检查点；采集完成后发生中断，不因恢复任务而盲目重复采集。
- 每个账号同一时刻只允许一个协作流程；操作系统文件锁会在进程退出后释放。

## 输入与交接

### 对话附件

将文件拖入输入框或对话区，或点击输入框左下角“＋”；复制的截图可直接粘贴到输入框。图片展示缩略图，视频展示封面和时长，文档展示名称与格式；多附件横向排列，移除按钮在悬停或键盘聚焦时显示。图片可点击放大，视频可点击播放。发送后，附件在消息中自动换行排列，并可重新打开本地副本。

普通文件均可添加，单文件、批次总大小和文件数量不设置上传上限；原件分块复制并保存在本机。可直接解析 ZIP/7z/RAR/TAR/GZ/BZ2/XZ，PDF、现代 Office、XLS、ODT/ODS/ODP、RTF、EPUB、EML、Notebook，以及常见代码、配置、字幕、日历、通讯录和文本格式。图片增加 HEIC/HEIF/AVIF，视频增加 MPEG/FLV/WMV/3GP/MTS 等格式。暂时无法解析的二进制格式仍保留原件，标明解析状态。

压缩包建立完整素材索引和缩略图联系表，每个文件有稳定编号。所有可读图片和视频封面都进入工作区；总览逐批浏览全部联系表，完成的观察逐项保存。成员可以检索文件名或画面描述，按编号查看原图、指定区域或视频时间点。解码失败、总览未完成、原图已细看分别记录。加密、链接及不安全路径的成员保留明确状态。

原件复制到当前账号的 `attachments/blobs`，索引、缩略图、观察和细看结果与会话关联。移动源文件不影响历史；中断后复用已完成批次和已检查原图。较长文本可从原件按字符位置继续分段读取。扫描 PDF 页面转为图片后持续分批处理。模型调用失败会保存进度和具体原因。

联系表只是工作批次，不是整个任务的总量截止。图片细节可重新打开原图或局部放大；视频首帧只用于总览，进一步检查时可提供具体秒数列表，继续读取其他画面。总览进度和原图/视频细看进度独立显示，音轨尚未转写。文档文字以工作窗口预览提供，原件完整保留；公式、脚本和宏不会执行。

附件可进入普通问答，也会作为固定方案流程的冻结证据。恢复任务沿用已保存的附件资料，按最新数据重做仍保留原附件。

### 普通对话的执行记录与恢复

普通对话使用独立的持久化执行记录，与固定团队流程共用账号执行锁。任务卡可查看操作结果；失败、停止或进程退出后，从历史会话点击“继续未完成任务”。已完成的操作使用原结果，不重新执行。

需要确认的操作先保存具体请求，再显示确认卡；决定与请求绑定。已拒绝的相同请求不再重复询问。尚未决定的请求恢复时使用原有效期，过期不会执行。已批准但未开始的请求也不能在有效期外自动执行。

执行中断的只读查询可以重试，并消耗新的尝试额度。采集、指标补录等写操作若无法确认是否完成，会显示“请核对上次操作结果”，继续按钮禁用；在对应数据页面核对后，再提出新的具体要求。

附件任务按实际文件和用户目标持续推进，不受普通聊天的工具次数、模型次数或总时长额度约束；用户可以停止并继续。较早的工具上下文压成工作窗口，完整执行记录、素材索引和观察留在本地，成员可按需查询。网络错误与无进展的重复失败会明确停下并保留恢复入口。非附件对话沿用原有执行额度。

模型名、token 用量、耗时及调用目的保存在本地；普通回复记录该任务已返回的聚合用量。长期摘要使用消息 ID 游标，不依赖最近历史的窗口长度；摘要失败时不会跳过原文。

### 固定团队流程的证据快照

整理数据阶段在一个 SQLite 读事务中冻结：当前账号标识、企业资料、最新至多30条本人作品、这些作品的有效互动者统计与至多20个公开资料样本、采集覆盖情况、指标来源及时间。
如果用户明确指定近若干天，按作品发布日期筛选；未知发布日期的作品不混入该范围。

受众与内容分析独立读取同一个快照。策略阶段接收已保存的两份分析成果，并保留原始证据及信息缺口。
分析成果中的观察与假设必须分开，引用编号必须存在。结构或引用错误最多修正一次，仍不合格时中断，保留先前成果。
程序的结构校验不能证明分析结论在语义上成立，发布前仍需人工核实。

没有有效互动者时跳过受众分析；没有本人作品时跳过作品诊断。方案仍可根据用户提供的企业资料生成建议，但任务会标注部分完成，不会声称完成了缺少依据的分析。

## 实现入口

- `analyze/conversation.py`：普通对话路由、方案按钮、继续和重做的统一入口。
- `analyze/workflow.py`：固定流程、阶段校验、确认采集、取消与交付。
- `store/workflow.py`：任务、步骤、检查点、成果、数据快照和账号执行锁。
- `db/migrations/0014_workflows.sql`：新增三张协作表，不改动旧迁移和采集任务队列。
- `desktop/harness.py`、`desktop/window.py`：任务卡、阶段成果、状态事件与恢复按钮。

阶段成果与对话消息在同一事务提交；方案、方案成果和会话关联也在同一事务提交。后续步骤仅在前序成果落库后启动。

## 验证范围

自动化验证覆盖固定快照、真实成果交接、失败后重新打开数据库继续、按最新数据重做、停止后继续、拒绝补采、部分采集结果、无效引用拒绝、跨会话和账号检查、日期范围，以及真实 Qt 按钮与信号链路。
浏览器扫码与抖音采集仍须在真实环境中单独完成业务验收，不能以模型或界面测试替代。
