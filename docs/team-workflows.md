# 团队连续协作

普通问答仍由一名成员回答。受众分析、作品诊断和传播方案进入程序管理的固定流程。

## 使用

- “仅用已有数据，分析受众和作品，给我三个下周选题”：整理数据 → 受众分析 → 作品诊断 → 制定方案 → 汇总交付。
- “仅用已有数据，分析互动人群”：整理数据 → 受众分析 → 汇总交付。
- “仅用已有数据，诊断作品表现”：整理数据 → 作品诊断 → 汇总交付。
- “更新数据后生成方案”：由数据管家先检查登录态，登录和采集分别通过现有确认卡授权，再进入分析。
- “生成方案”按钮：使用已有数据和当前会话进入同一个协作入口。

拒绝登录或补采后，程序只根据已有数据继续；缺失的分析阶段会明确标为资料不足，任务标为部分完成。

## 成果与恢复

任务卡显示各成员的状态。“查看阶段成果”可查看分析、方案、样本范围、数据冻结时间和引用依据。
完整方案沿用原有右栏、人工复核记录和导出报告功能。

- **继续未完成步骤**：沿用原来的数据快照和已完成成果，从失败、停止或上次未结束的步骤继续。
- **按最新数据重做**：新建任务、重新读取本机数据；原任务及成果保留。是否联网采集仍遵循原请求的范围及确认流程。
- 程序重启后，从历史会话重新打开任务即可继续；不会在启动时自动执行浏览器操作。
- 已成功采集的结果会先记录检查点；采集完成后发生中断，不因恢复任务而盲目重复采集。
- 每个账号同一时刻只允许一个协作流程；操作系统文件锁会在进程退出后释放。

## 输入与交接

整理数据阶段在一个 SQLite 读事务中冻结：当前账号标识、企业资料、最新至多30条本人作品、这些作品的有效互动者统计与至多20个公开资料样本、采集覆盖情况、指标来源及时间。
如果用户明确指定近若干天，按作品发布日期筛选；未知发布日期的作品不混入该范围。

受众与内容分析独立读取同一个快照。策略阶段接收已保存的两份分析成果，并保留原始证据及信息缺口。
分析成果中的观察与假设必须分开，引用编号必须存在。结构或引用错误最多修正一次，仍不合格时中断，保留先前成果。
程序的结构校验不能证明分析结论在语义上成立，发布前仍需人工核实。

没有有效互动者时跳过受众分析；没有本人作品时跳过作品诊断。方案仍可根据用户提供的企业资料生成建议，但任务会标注部分完成，不会声称完成了缺少依据的分析。

## 实现入口

- `analyze/conversation.py`：普通对话路由、方案按钮、继续和重做的统一入口。
- `analyze/workflow.py`：固定流程、阶段校验、确认采集、取消与交付。
- `store/workflow.py`：任务、步骤、检查点、成果、数据快照和账号执行锁。
- `db/migrations/0014_workflows.sql`：新增三张协作表，不改动旧迁移和采集任务队列。
- `desktop/harness.py`、`desktop/window.py`：任务卡、阶段成果、状态事件与恢复按钮。

阶段成果与对话消息在同一事务提交；方案、方案成果和会话关联也在同一事务提交。后续步骤仅在前序成果落库后启动。

## 验证范围

自动化验证覆盖固定快照、真实成果交接、失败后重新打开数据库继续、按最新数据重做、停止后继续、拒绝补采、部分采集结果、无效引用拒绝、跨会话和账号检查、日期范围，以及真实 Qt 按钮与信号链路。
浏览器扫码与抖音采集仍须在真实环境中单独完成业务验收，不能以模型或界面测试替代。
