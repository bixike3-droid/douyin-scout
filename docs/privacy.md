# 数据与隐私

> 本文描述源镜在这台电脑上如何处理数据，以及使用者的责任边界。
> 它说明程序**实际做了什么**，不构成法律意见；对外提交前请自行核对适用法规与平台条款。
> 程序内左下角账号菜单 →「隐私说明」提供了简版；本文件是完整版。

## 一、适用范围

- **单机、单用户、自用**：数据只存在运行它的电脑上，不提供服务器、多用户或对外 API。
- 数据目录随部署方式不同（见第三节）。桌面版的所有数据都在本机磁盘上，没有云端账号体系。
- 只有使用者**主动**调用在线模型做分析时，才会向外发送内容（见第七节）。

## 二、技术边界：程序做了什么、没做什么

| 程序会做 | 程序不会做 |
|---|---|
| 用使用者自己登录的真实浏览器发请求，读取浏览器已经拿到的响应 | 不实现、也不引入第三方请求签名（`a_bogus` / `msToken` / `X-Gorgon`） |
| 单实例、单 IP、低频访问；请求之间有固定下限与随机抖动 | 不伪造浏览器指纹，不上 stealth 插件，不改 `navigator.webdriver` |
| 按日配额与熔断停手，不追求"采完" | 不破解、不代答验证码，不使用打码平台 |
| 归档响应正文，解析失败可回放重解 | 不使用代理池、不做并发 |
| 只在使用者确认后执行登录、采集、评论采集、指标补录 | 不自动发布、不自动私信、不做任何"代操作" |
| —— | 不托管他人账号，不对外提供服务或分发数据 |

**这段边界不等于"平台一定允许自动化访问"。** 自动化访问是否被抖音的用户协议允许，
取决于账号授权、使用目的与平台当时的规则；本程序不作保证，由使用者自行确认。

## 三、采集与存储了哪些数据

以下字段来自抖音页面对**该账号可见的公开信息**，用于分析互动受众与作品表现。

| 类别 | 具体内容 | 存放位置 |
|---|---|---|
| 登录态 | 浏览器 cookie（含 `sessionid`）、浏览器配置目录 | `<数据根>/data/accounts/<账号>/profiles/` |
| 互动者资料 | `sec_uid`、抖音号、昵称、头像地址、签名、性别、地区、IP 属地、粉丝/关注/获赞/作品数、认证信息、首次与末次出现时间 | SQLite `users` 表 |
| 互动关系 | 谁在哪个作品上点了赞、评论内容与点赞数 | `like_edges`、`comments` 表 |
| 本人作品 | 公开作品列表、播放/点赞/评论/转发数、封面与播放地址 | `works` 表 |
| 作品媒体副本 | 只有点「保存到本机」才下载的视频 | `<数据根>/data/accounts/<账号>/state/work-media/` |
| 热点视频副本 | 只有点「交给团队」才下载的热点视频 | `<数据根>/data/accounts/<账号>/state/hot-videos/` |
| 原始响应 | 归档的接口响应正文，可能包含上述字段及页面上的其他公开信息 | `<数据根>/data/accounts/<账号>/raw/` |
| 使用痕迹 | 请求日志、任务记录、事件日志 | SQLite + `logs/` |
| 使用者导入的附件 | 图片、视频、PDF、Word、表格、压缩包及其缩略图/转码预览 | `<数据根>/data/accounts/<账号>/state/` |
| 导出文件 | 手动导出的 CSV、报告 | `<数据根>/data/accounts/<账号>/exports/` |

**不采集**：私信内容、手机号、身份证件、支付信息、通讯录、实时位置轨迹。
`ip_location` 是抖音公开展示的 IP 属地，不是精确位置。

需要明确的是：互动者资料与互动关系属于**第三方个人信息**。本程序把它们保存在本机，
只供使用者本人做运营分析，但这不改变"这些是他人个人信息"的事实——留存时限、对外提供
和公开使用都要按下面的约定处理。

数据根的位置：

| 使用方式 | 数据根 |
|---|---|
| 源码运行（`desktop-html/启动.bat`） | `desktop/userdata/` |
| 打包版 | `%LOCALAPPDATA%\douyin-scout\` |
| 只用 CLI | 项目根目录下的 `data/`（可用 `SCOUT_DATA_DIR` 覆盖） |

每个账号单独一个目录：`data/accounts/<账号>/{db,profiles,raw,logs,exports,state}`。
换账号就是换目录，不会互相污染。

## 四、用途限制

- 只用于**使用者本人账号**的运营分析：互动受众画像、作品表现诊断、选题与复盘。
- 不对任何个人做出自动化决策，不用于评估个人信用、身份或权益。
- 不对外提供、不出售、不在网上公开发布；团队内部协作时也不共享整个数据目录。
- 不用于训练第三方模型，不投喂到公开数据集。
- 需要在汇报、参赛材料或公开场合展示时，先做匿名化：昵称、头像、抖音号、`sec_uid` 打码。

## 五、保留期限与清理

默认值来自 `config/default.yaml` 的 `storage` 段，可以按需修改。

| 内容 | 默认保留 | 说明 |
|---|---|---|
| 归档响应正文 | 7 天 | 只删正文，保留 `sha256/url/大小/采集时间` 等元数据 |
| 请求日志 / 事件日志 | 30 天 | —— |
| 已完成任务 | 14 天 | `pending` / `failed` 不受影响 |
| 点赞关系陈旧标记 | 30 天 | **只标记不删除**，避免接口偶发不全时误删真实数据 |
| 数据库、导出、附件 | 不自动删除 | 随账号目录长期存在，需要手动清理 |
| 作品媒体副本 | 不自动删除 | 播放默认不落盘；保存的副本可在「设置 → 本地数据」查看占用并一键清空 |

```powershell
# 预览将清理什么（默认 dry-run，不会动手）
.venv\Scripts\python.exe -m scout.cli cleanup

# 确认执行
.venv\Scripts\python.exe -m scout.cli cleanup --apply

# 临时改保留天数（示例：归档正文保留 3 天）
.venv\Scripts\python.exe -m scout.cli cleanup --raw-days 3 --apply

# 清理历史遗留的静态资源归档（不碰数据接口的归档）
.venv\Scripts\python.exe -m scout.cli prune --dry-run
```

## 六、导出与删除

```powershell
# 导出互动者 / 作品 / 点赞关系为 CSV（utf-8-sig，Excel 直接打开）
.venv\Scripts\python.exe -m scout.cli export --table users
.venv\Scripts\python.exe -m scout.cli export --table works
.venv\Scripts\python.exe -m scout.cli export --table like_edges
```

**删除某个账号的全部数据**：关闭程序后删除该账号目录，不可恢复。

```powershell
# 打包版
Remove-Item -Recurse "$env:LOCALAPPDATA\douyin-scout\data\accounts\main"
# 源码运行
Remove-Item -Recurse "desktop\userdata\data\accounts\main"
```

**彻底卸载**：删除程序目录，再删除上面列出的数据根目录。

**删除某位互动者的数据**（应对个人提出的删除请求）：

- 界面：互动受众 → 详情 → 「删除此人数据」，确认前会显示将删除多少条。
- 命令行：先用 `.venv\Scripts\python.exe -m scout.cli forget <sec_uid>` 预览，确认后加 `--apply` 执行。

删除范围：该人的资料、点赞与评论记录、指标快照、作品样本、AI 分析结果，
以及针对他的待办任务与采集覆盖记录；他名下的公开作品样本和相关互动一并删除。

**不删除**：归档正文（`raw/`）、已导出的 CSV、备份文件。
这些需要另行按时间段整体清理，或直接删除对应的导出文件。

## 七、调用在线模型时发送什么

- 默认调用使用者自己配置的模型服务（`config/llm.local.yaml` 的 `base_url`，默认 DeepSeek 官方接口）。
- 发送的是**你主动请求的分析所需的摘要**：作品指标、昵称/评论等文本片段、你导入的附件内容；
  图片会按模型能力压缩，视频按时间点抽帧。
- **不发送**登录 cookie、数据库文件、完整归档目录。
- API Key 只存在本机 `config/llm.local.yaml`，不写入数据库，报错信息会自动打码。
- 模型服务商对请求内容的处理适用其自身条款。涉及敏感数据时，请自行评估是否改用
  本地模型或已签署数据处理协议的供应商。
- 把热点视频交给团队时，视频会作为对话附件保存在本机，并按既有规则抽取画面；抽样画面与公开指标会发送给你配置的视觉模型。
- **检查更新**只请求自建版本源（失败时回退 GitHub Releases）读取版本号与下载地址，
  不发送机器名、账号或任何本机数据；下载的安装包只写入 `<数据根>/updates/`。

## 八、使用者责任

1. 只采集**你有权访问**的账号与数据；档 A（登录态）使用小号，不用主号。
2. 遵守抖音的用户协议与频率限制。本程序降低频率只是为了稳定与不打扰，
   **不构成平台许可**。
3. 不把采集结果公开发布或用于骚扰、人肉、精准营销等用途。
4. 不针对未成年人采集或分析；如发现数据中包含未成年人，应删除。
5. 对外展示前先匿名化；不要把原始 CSV、数据库或截图原样贴到公开渠道。
6. 多个使用者共用一台电脑时，各自使用独立的系统账号或独立数据根，不要共用数据目录。

## 九、对外表述建议

需要写进材料、报名表或说明会时，可以直接使用下面这段（与程序实际行为一致）：

> 源镜是单机本地运行的抖音运营分析工具，只读取使用者本人已登录账号可见的互动与作品数据。
> 程序不实现请求签名、不伪造浏览器指纹、不破解验证码，不使用代理池或并发，访问频率保持在
> 日常使用量级。数据仅保存在本机，默认 7 天清理归档正文、30 天清理日志，可随时导出或整体删除。
> 只有在使用者主动调用在线模型时才发送必要的文本与指标摘要。工具按使用者自身授权使用，
> 自动化访问是否被平台允许由使用者确认。

## 十、已知缺口

- 按人删除已提供（见第六节），但还没有批量匿名化 / 脱敏导出的功能。
- 归档正文不做字段级脱敏，可能包含页面上的其他公开信息，清理只能按时间段整体删除。
- 导出的 CSV 与 SQLite 均为明文，**没有加密存储**；磁盘权限就是唯一边界，
  共用电脑时请使用独立的 Windows 账号。
- 附件转码预览（`state/html-previews/`）、作品媒体副本（`state/work-media/`）与热点视频副本
  （`state/hot-videos/`）不参与按天清理；长期使用需要手动删除目录，或在设置页清空作品媒体。
