# 源镜 · 企业需求清单与程序说明

> 面向对象：需要做抖音内容运营的中小企业/文旅单位（当前样例：乌兰察布文旅）。
> 状态标记：✅ 已具备（有测试/真机验证）· 🟡 部分具备 · ⛔ 尚未具备。

| 12 | 账号与数据安全 | 账号被封=业务停摆 | 单账号隔离、频率护栏、熔断；原始数据本地留存 | ✅ 双档 + 配额/节奏/熔断 + 归档 |
| 13 | 合规可控 | 不做灰产式刷量 | 只读公开数据，不模拟登录他人、不批量养号 | ✅ 设计即此边界 |
| 14 | 断点与恢复 | 采集中断不能白跑 | 任务可续采、失败进退避、幂等入库 | ✅ 覆盖率 + 任务锁 |

### 6. 结论：现在最缺的三件事

1. **真机端到端跑通一次**（登录 → 采集 → 分析 → 报告），目前所有模块都有测试，但完整业务闭环还没在真实账号上走过一遍。
2. **可安装的交付形态**（安装包 / 免配置浏览器），否则只有开发机能跑。
3. **评论区洞察（阶段 3）**：这是"从数据到动作"最后一公里，目前只有原始评论。

## 二、程序总体说明

### 一句话

**源镜**是一个装在 Windows 上的单机桌面工具：用真实浏览器采集抖音公开数据，交给内置 AI 团队分析，产出可交付的传播方案与复盘报告。

### 形态与技术

| 项 | 说明 |
|---|---|
| 形态 | Windows 桌面程序（PySide6 / Qt），无服务器、无云端账号体系 |
| 数据 | 本地 SQLite（单库、编号迁移到 0017），原始响应另存归档目录 |
| 采集 | Playwright 驱动真实 Chromium，由页面自己发请求，程序只读响应 |
| AI | 可配 DeepSeek（兼容 Anthropic 端点），也支持其它 OpenAI 兼容模型 |
| 界面 | Apple 风格设计，浅色/深色/跟随系统；无边框窗口 + 系统原生最小化/最大化动画 |

### 页面结构（8 页）

1. **传播工作台**：AI 团队对话、热点、内容方案三栏
2. **作品数据**：自己作品列表 + 详情（含已采点赞人、评论区）
3. **互动者**：互动过的人 + 画像 + 互动作品
4. **历史分析**：历史报告与复核
5. **采集任务**：任务状态、重试、错误
6. **对标账号**：名单 + 更新检查
7. **设置**：模型 Key、采集参数、外观
8. **数据概览**：总量、质量、最近事件

### AI 团队（7 位成员）

源镜（总管/调度）、数据管家、受众分析师、内容分析师、热点观察员、传播策略师、复盘顾问。

- 一条消息**广播全队**，调度器自动派单，发言人署名
- 7 个工具：网页读取、联网搜索、抖音热点榜、数据概览、记录检索、登录抖音、开始采集
- 高风险动作（登录、采集）走**确认卡**，决策记审计
- 连续协作：受众分析 → 内容分析 → 方案，阶段成果可见、可停止、可续跑
- 回复末尾可给**可点击选择题**，选完自动继续对话；分析结论可出**流程图**（对话内渲染，可双击放大）

### 数据链路

```
真实浏览器 → 页面内请求 → 原始 JSON 归档(raw_blobs)
          → 解析(parse) → 幂等入库(SQLite) → 覆盖率/质量检查
          → AI 分析(受众/内容/方案/复盘) → 报告与对话
```

### 采集与合规（这套是程序的地基）

- **双档位**：登录档（扫码一次，长期复用）+ 匿名档；按需惰性启动
- **抽样预算**：小名单全采，大名单按比例抽样并封顶（默认 40%、下限 20、上限 100）
- **护栏**：每日配额、请求节奏、连续失败熔断
- **任务锁**：同一对象同时只跑一个任务；失败进退避；可续采
- **归口**：点赞/评论都必须挂到具体作品，不存"无主"数据
- **审计**：每次请求记 telemetry，原始响应可回放核查

### 已有能力清单（简）

- 采集：本人资料、作品列表、互动通知、点赞人、评论、用户作品、公开资料
- 分析：受众画像、作品评价、传播方案、历史复盘、报告修订
- 热点：抖音官方热榜直连 + AI 可用性评估 + 快照历史 + 失败回落
- 交互：确认卡、选择题、图卡、思考过程、停止/重试、历史会话
- 系统：启动页（真实阶段）、任务栏进度、主题跟随、崩溃日志

### 边界与未验证（必须知道）

- ⛔ 还没有在**真实账号**上完整跑通"登录→采集→分析→报告"
- ⛔ 没有安装包；全新电脑不会自动装浏览器，采集会断
- 🟡 评论接口的字段结构是首版实现，需真机核验
- 🟡 Mica 材质暂缓（会破坏窗口拖动），已关闭
- 不做：刷量、养号、自动化互动等灰产能力

### 运行方式

- 源码模式：`.venv\Scripts\python.exe desktop\app.py`（开发/测试用）
- 数据位置：`desktop\userdata`（数据库、日志、归档、配置）
- 文档：`docs/product.md`（产品定义）、`docs/architecture.md`（架构）、`docs/status.md`（进度与验证）、`docs/runbook.md`（运维）
