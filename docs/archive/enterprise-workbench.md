# 源镜 · 竹梦村传播决策

当前界面已调整为深色三栏任务工作台，操作入口以 [`yuanjing-ui.md`](yuanjing-ui.md) 为准。
以下保留企业数据与分析流程的说明。

本轮依据团队作品简介，将默认桌面流程调整为企业资料、作品复盘、内容决策、人工复核及执行反馈。
业务目标是通过自媒体吸引散客、增加客户。企业缺乏运营团队、内容重复、效果不佳是待调研的问题，
程序不会直接把这些表述当成已证实的竹梦村现状。

## 一页使用说明

1. 打开 `dist/打开工作台.lnk`，默认进入“竹梦村推广”。
2. 在“企业资料”填写已确认的文旅特色、本次推广产品、资料来源与确认时间；补充受众依据、预算和执行限制。
   名称、地点及业务目标有初始值；当前价格、活动、开放时间和预约渠道没有预填。
3. 在顶部“登录抖音”，在“采集任务”采集当前账号的数据。已有登录、采集及历史分析入口保留。
   确认当前账号的本人作品与竹梦村宣传有关后，勾选企业页的关联确认并保存。
   未确认时不发送账号作品；这也支持先用企业资料生成标明信息缺口的草案。
4. “账号作品”展示播放、点赞、评论和转发。播放量缺失显示“未获取”；“作品数据补录”可选择本人作品，
   录入后台真实指标、统计日期、来源及内容说明。未知留空，真实为零填 0。补录保留历史，不覆盖接口原始数据。
5. 在“设置”保存自己的 DeepSeek Key，然后在“传播决策”生成建议。
   将发送企业资料、至多30条已关联本人作品的标题/简介和指标、用户提供的内容说明，以及所填执行反馈。
   不发送本流程之外的互动者个人画像。相同资料、模型配置和提示词版本默认复用报告。
6. 阅读诊断、内容优化、个性化选题、渠道策略、复盘指标和信息缺口。右侧依据显示 E1/E2/E3/W 等证据编号与来源。
   检查价格、活动、历史表述、预约渠道和实际接待条件后修改稿件，填写修改/复核说明，保存人工稿。
   勾选人工核对仅代表用户声明；编辑稿件会撤销该勾选。模型原稿和全部人工版本保留。
7. 导出 Markdown 决策记录，包含当前保存稿、原始模型建议、输入快照、提示词与修改记录。
   执行后回到“企业资料”，记录具体动作、作品、统计周期和结果来源，并选择对应的历史报告。
   再次生成时会带入历史建议、执行反馈与当前作品数据，形成下一轮复盘。

## 数据与分析边界

- 播放量按接口实际返回展示，不保证公开接口提供所有后台指标。播放补录是用户行为，不能称为程序自动获取。
- 内容分析使用标题/简介、人工内容说明和统计，没有自动观看视频、转写声音或分析画面。
  缺少正文、完播率、留存或现场资料时，不能据此断言视频节奏、真实体验或转化效果。
- 指标保留各自来源与统计时间；不同时间、来源的数值不应直接组合计算比率。
  新报告保留当时输入，后续更新不改变历史输入快照。
- 引用校验检查结构完整和编号存在，不能自动证明建议符合事实；需要人工核对。
- 当前未自动采集咨询、订单、预约或到店数据。执行反馈由用户记录并标注来源。
  点赞者不等同游客，互动增长不等同客户增长。
- 与抖音平台相关的登录、接口限制和403问题仍受外部状态影响，本轮没有解除平台限制。
- 数据按现有账号目录隔离；企业资料存于对应本地数据库。密钥与浏览器登录态不进入发行包。

## 赛道三证据准备

工具保留实际提示词、输入快照、模型及耗时/Token数据、原始输出和人工修改记录。
团队仍需使用运营方核实的资料，提供典型、复杂和边界三个真实运行案例，并开展非团队成员试用。
软件测试和公开资料模型调用只能证明技术流程，不能替代企业试用、传播效果或效率改善证据。

建议同步调整作品简介：

> 面向乡村文旅企业的自媒体内容决策需求，本作品以竹梦村为应用场景，开发原生桌面端AI传播决策工具。
> 工具结合企业特色、推广产品与经营约束，展示已获取的作品播放、点赞、评论等指标，并支持有来源的后台数据补录。
> 大模型基于作品标题、内容说明和互动表现生成传播诊断、内容优化、个性化选题与策略建议，保留依据及信息缺口。
> 用户可复核、修改和导出建议，将执行反馈关联历史报告开展下一轮分析，为内容策划提供可追溯的决策支持。

“缺乏专业运营团队”“内容重复”“传播不理想”等具体问题，应在访谈和数据诊断后据实补充。
