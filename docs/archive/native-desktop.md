# 原生桌面基底

主入口使用 PySide6 / Qt Widgets。界面直接调用桌面服务，读取本机 SQLite。
桌面依赖固定为 PySide6-Essentials 6.8.3，开发验证环境为 Windows 11 / Python 3.13。

当前源镜更新包为 `dist/yuanjing/源镜.exe`。本机可双击 `dist/打开源镜.lnk` 或 `dist/打开工作台.lnk`，
继续使用原程序 `dist/userdata` 中的数据和设置；`dist/查看已有数据.lnk` 查看项目中的历史采集数据。

## 当前可用

当前布局与交互动效见 [`yuanjing-ui.md`](yuanjing-ui.md)；左栏历史与中栏处理阶段对应真实报告和运行事件。

- 默认进入竹梦村推广：企业资料、可追溯建议、人工修改与导出、指标补录和执行反馈复盘。
  一页使用说明及当前验证范围见 [`enterprise-workbench.md`](enterprise-workbench.md)。

- 概览：作品数、互动人数、分析历史、待处理任务及最近日志。
- 我的作品、互动者、分析报告、任务记录：搜索、每页 100 条、完整记录详情。
- 设置：保存用户自己的 DeepSeek Key 和模型名称，密码输入、打码展示、原子写入。
- 后台工作队列：数据库连接在工作线程内建立并关闭，结果经 Qt 信号回到窗口。
- 初始化数据库，退出时等待正在进行的本地操作完成。
- 深色导航与浅色工作区，统一图标、字号、状态颜色和应用图标。
- 概览展示最近作品、任务状态分布与活动记录；小窗口通过滚动保持内容可读。
- 列表与详情左右排列，可收起详情面板；空记录和无搜索结果有独立提示。
- 记录详情使用中文字段，报告建议以条目展示；时间统一显示为上海时区。

操作入口：窗口顶部“登录抖音 / 重新登录”；“采集任务”中“开始采集”；
“历史分析”中“分析互动者 / 评价我的作品 / 生成内容计划”；“竹梦村推广”中生成企业传播建议。
这些操作复用现有业务模块，在可取消的独立工作线程中执行。
快速 / 深采及质量筛选的规则与实测边界见 [`collection-upgrade.md`](collection-upgrade.md)。
同一时间仅执行一项长任务，停止或退出时等待会话关闭；数据查询仍可使用。
登录会打开可见浏览器，扫码或验证码由用户操作；服务端确认本人身份后自动保存登录态。
已有分析按对象与报告类型显示最新一份，概览中的“分析历史”是所有历史结果数量。

## 开发启动

```powershell
.\.venv\Scripts\python.exe -m pip install -e ".[desktop]"
.\.venv\Scripts\python.exe desktop\app.py
```

也可以双击 `desktop/启动.bat`。

`desktop/app.py` 默认继续使用 `desktop/userdata`；打包程序默认使用 exe 旁的 `userdata`。
程序目录无法写入时使用当前用户的本地应用数据目录。
可用 `--data-dir <目录>` 指定独立的数据根目录，显式指定不可写目录会报错。
运行 `python -m scout.desktop` 默认使用 `SCOUT_ROOT` 或当前用户的本地应用数据目录。

默认配置从发行包复制到持久配置目录；用户的 `local.yaml`、`llm.local.yaml` 放在该目录，
重启和重新解包不覆盖。原先仅位于项目 `config/llm.local.yaml` 的 Key 需在新界面重新填写。
原先 `data/accounts` 中的开发数据不会自动搬移；需要查看它们时用 `--data-dir` 指向该 data
目录的父目录。切换目录不会合并数据库。

保存设置仅写入本机，不验证连通性或进行付费调用。未来执行分析时，相关公开资料与作品摘要
会发送给用户配置的 DeepSeek 服务。

## 打包与验证

`desktop/打包.bat` 使用 PyInstaller 生成 `dist/yuanjing/源镜.exe`，仅打包默认配置和 SQL 迁移。
不得附带任何用户密钥、数据库或浏览器登录态。

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

`tests/test_desktop.py` 检查持久配置、分页与字面量搜索、报告去重、工作线程、选择详情及退出。
Qt 测试使用 offscreen 平台；没有安装桌面可选依赖的环境会跳过 Qt 测试。

## 后续接入约定

- 窗口通过服务执行业务，不在界面中写 SQL。
- 每个后台任务持有独立数据库连接，不跨线程共享 AppContext。
- 登录、采集和分析由 `Operations` 管理，不放入短任务队列。
- 登录与采集共同保护浏览器会话；取消、失败和退出必须先关闭会话再释放上下文。
- 分页异常和部分完成状态修正后再接入“采集完成”展示。
