## 1. 最关键的问题：点赞人列表在网页版是否可见

这一条决定整个方案能不能走浏览器路线。

| 问题 | 结论 | 证据（probe 报告 / 截图） |
|---|---|---|
| 登录后「消息-赞」在**网页版**是否存在？ | 是 / 否 | |
| 实际页面地址是什么？ | | |
| 能否看到点赞人的**身份**（昵称/sec_uid）？ | 是 / 否 | |
| 单次能看到多少条？ | | |
| 滚动到底会怎样？（继续加载 / 停止 / 弹登录 / 空白） | | |
| 是否能看到该点赞人**赞的是哪个作品**？ | 是 / 否 | |
| 时间跨度有多长？（只有最近 N 天？） | | |
| 有没有「查看全部」入口？ | 是 / 否 | |

**结论填写：**

```
（例：网页版存在通知流，只保留最近约 200 条，无按作品聚合的完整名单，
  无"查看全部"入口。因此可自动化采集的上限就是这约 200 条。)
```

> ⚠️ 如果这一节结论是「网页版没有」，方案要改成 App 端自动化，
> 难度和风险完全不是一个台阶 —— 到时候停下来重新评估，不要硬上。

## 附：勘探命令备查

```powershell
# 勘探匿名态的用户主页
.\.venv\Scripts\python.exe -m scout.cli probe --url "https://www.douyin.com/user/<SEC_UID>" --tier b --scroll 6

# 勘探登录态的通知流（先把真实地址填进 local.yaml 或用 --save-endpoint）
.\.venv\Scripts\python.exe -m scout.cli probe --url "<你登录后打开的消息页地址>" --tier a --scroll 5 --save-endpoint notice_url

# 报告会写到 exports\probe-<时间戳>.md，正文归档在 data\raw\
```
