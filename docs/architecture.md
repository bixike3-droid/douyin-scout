# 架构

## 一、这个项目要解决什么

把你**手动能看**的东西自动化：登录自己的抖音账号，看点赞人 → 逐个点开主页 → 做用户分析。
手动点太累，程序代劳。

它**不解决**的问题，也不打算解决：

- 不实现抖音的请求签名（`a_bogus` / `msToken` / `X-Gorgon`）
- 不绕过任何技术保护措施
- 不做多用户对外服务
- 不追求速度。速度从来不是瓶颈，配额才是

## 二、核心技术选择：让浏览器去请求，我们在旁边收

```
                 ┌─────────────────────────────────────────┐
                 │  Playwright（一个实例）                  │
                 │                                          │
  档 A 登录态 ──▶ │  context_A  persistent profile          │
                 │    └─ 只访问「消息-赞」，解析 sec_uid      │
                 │                                          │
  档 B 匿名态 ──▶ │  context_B  全新 context（独立 cookie）   │
                 │    └─ 承载全部公开数据采集                │
                 └───────────────┬─────────────────────────┘
                                 │ 真实浏览器发请求
                                 │ 签名由页面自身的 webmssdk.js 生成
                                 ▼
                        ResponseMirror（响应镜像）
                                 │ 抄一份响应
                                 ▼
                         RawArchive（原始归档，永不丢）
                                 │
                                 ▼
                    Parser（容错解析，可回放重解）
                                 │
                                 ▼
                       SQLite（幂等 upsert）
                                 │
                                 ▼
                  分析层 / 本地面板（只读）
```

**为什么这样最好：**

| | 自己实现签名 | 本方案（浏览器代发） |
|---|---|---|
| 签名维护 | 每次改版都要逆向，无底洞 | 零维护，页面自己算 |
| TLS/指纹 | 需要另外伪造 | 天然真实 |
| 合规风险 | 可能构成「绕过技术措施」 | 只是自动化用户自己的操作 |
| 速度 | 快 10~30 倍 | 慢 |
| **实际数据量** | **完全一样**（受配额限制） | **完全一样** |

最后一行是关键：既然日配额是固定的，快 30 倍只是让你更早撞验证码。

## 三、两档权限模型

| 档位 | 身份 | 职责 | 日配额 | 落地 |
|---|---|---|---|---|
| A | 登录态（**小号**） | 只解析点赞人列表，拿 `sec_uid` | 默认 60 | `data/profiles/tier_a` |
| B | 匿名态（无登录） | 全部公开数据：资料、作品列表 | 默认 1200 | 内存 context，不落盘 |

铁律：**档 A 绝不点进用户主页。** 它的请求数应该只有「通知流翻了几页」这么多，
一天几十个请求，风控几乎不可能注意到。所有重活都由档 B 承担。

`sec_uid` 是两档之间的唯一桥梁：档 A 只交出一个 ID，档 B 用
`https://www.douyin.com/user/<sec_uid>` 去取公开数据。

## 四、模块职责

| 模块 | 职责 | 不做什么 |
|---|---|---|
| `paths.py` | 唯一的路径来源 | —— |
| `config.py` | 分层配置（默认 < local < 环境变量） | 代码里不允许出现魔法数字 |
| `db/` | SQLite 连接 + 编号迁移 | 不含业务逻辑 |
| `store/` | 归档、仓储、遥测、缓存 | 唯一的 SQL 出口 |
| `guard/` | 配额、熔断、节流 | **只做判断，不做存取** |
| `session/` | 双档上下文、profile 锁、响应镜像、登录态体检 | 不解析数据 |
| `collect/` | 模板方法：护栏 → 节流 → 导航 → 收响应 → 归档 → 落库 | 不含字段映射 |
| `parse/` | 容错解析（通用抽取 + 精确解析器） | 不碰网络、不写库 |
| `schedule/` | 任务领取、扇出、退避、断点续采 | 不做判断策略 |
| `lab/` | 可见性勘探（browser lab） | —— |
| `analyze/` | 画像与导出，只读 | 不联网 |
| `web/` | 只读观测台 + SSE 日志 | **不提供写操作入口** |

分层的意义：**采集与解析解耦**。抖音改版只改 `parse/`，`collect/` 一行不动。
解析器改完用 `scout replay <raw_id>` 对归档回放，数据自动回填，不用重新采。

## 五、护栏：长期稳定的全部含金量

三道关，每次采集都要过：

1. **配额**（`guard/quota.py`）
   按本地日期分桶，持久化在 `quota_ledger`，重启不清零。
   触到就抛异常、整档停下。**绝不为"数据完整性"超额。**

2. **熔断**（`guard/circuit.py`）
   抖音的降级处罚是**静默**的——不报错，只是开始返回空。
   所以：连续 N 次空返回 = 判定被降级 → 立即停。
   冷却后进 `half_open` 放行一次探测；失败则冷却加倍（45min → 90 → 180…）。
   这条是为了**不把一批空数据洗进分析结果**。

3. **节流**（`guard/throttle.py`）
   随机间隔 + 每 N 个请求插一次长停顿。固定间隔本身就是机器特征。

配套的是**可观测**：每个请求都落 `request_logs`（时间/URL/状态/字节/耗时/是否空返回）。
出问题时不是猜，是查。

## 六、长期可维护性的四个支点

1. **原始响应永不丢**（`store/raw_archive.py`）
   按 sha256 去重落盘 `data/raw/YYYY-MM-DD/`。抖音改版是必然的，归档是唯一的后悔药。
2. **幂等**（`store/repo.py`）
   全部 upsert。重复采同一条不产生脏数据。任务队列有唯一约束，不会重复入队。
3. **断点续采**（`schedule/engine.py`）
   进程崩溃后卡在 `running` 的任务，下次启动由 `reclaim_stuck()` 自动捞回。
4. **快照留痕**（`user_snapshots`）
   只存当前值会丢掉趋势。粉丝数按天留痕，才谈得上做趋势分析。

## 七、有意不做的事

| 做法 | 为什么不做 |
|---|---|
| 自己实现 a_bogus | 维护无底洞、风控更易识别、合规风险 |
| 伪造 `navigator.webdriver` / 上 stealth 插件 | 请求特征保持真实是核心优势，伪造等于抹掉它。要更真实请用 `browser.cdp_url` 连接你自己的浏览器 |
| 并发 / 代理池 | 风控最先抓并发特征。单 IP 低频是长期存活的前提 |
| 做成多用户网站 | 一旦托管他人账号并存储第三方个人信息，法律身份从「个人自用」变成「个人信息处理者」 |
| 在面板里放写操作 | 浏览器里误触就发出一堆请求，风险不可控 |

## 八、数据流的一次完整走查

```
scout run
  └─ Engine.run_round()
      ├─ tasks.reclaim_stuck()            # 捞回崩溃遗留
      ├─ Engine.seed()                    # 补入队：通知流 / 待办资料
      └─ for tier in [a, b]:
          loop:
            ctx.guard(tier)               # ① 配额 + 熔断，不过就整档停
            tasks.claim(tier, 1)          # ② 原子领取
            Collector.run(task)           # ③ 模板方法
              ├─ throttle.wait()          # ④ 拟人间隔
              ├─ session.goto(tier, url)  # ⑤ 真实浏览器导航
              ├─ humanize.interact()      # ⑥ 拟人滚动/鼠标
              ├─ mirror.drain()           # ⑦ 等响应抄完
              ├─ archive.save(...)        # ⑧ 先归档
              ├─ parse_payload(...)       # ⑨ 再解析
              ├─ quota.consume(tier)      # ⑩ 记账
              └─ circuit.record_*()       # ⑪ 熔断反馈
            tasks.complete / fail(backoff)
```

注意 ⑧ 在 ⑨ 之前：**解析可以随时重做，响应丢了就没了。**
